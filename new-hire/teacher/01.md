# Teacher notes, stop 1: The smallest program

## What the student should leave with

- Model against state, and that one model can have several states.
- What a step is, and that simulated time is a count of steps.
- Pointer, reference and value; `const`; what `*` and `->` do at a call.
- Ownership by scope: why `unique_ptr` exists and why it cannot be copied.
- That a compiler error is read from its first error and the notes under it.

## Lab results

Measured 2026-11-24 at commit `a091cc2`, GCC 14 on 64-bit ARM Linux. Compiler messages
differ between compilers; run them again.

1. `step_arm`: "500 steps of 0.002 s, simulated time 1.000 s". `shoulder_lift_joint`
   0.02415 rad and `elbow_joint` 0.00677 rad; the rest zero to four decimals. Those two
   joints carry the arm's weight against gravity; the pan joint's axis is vertical, so
   gravity does not turn it.
2. `duration = 5.0`: "2501 steps of 0.002 s, simulated time 5.002 s", and the same
   0.02415 rad. Two lessons. The sag is a balance, not a fall: the UR10e's motors are
   position servos (in its XML, `gainprm="5000" biasprm="0 -5000 -500"`: 5000 N m per
   radian of error), so 0.024 rad of error is about 120 N m, which is what gravity asks
   of the shoulder. And 2501, not 2500: adding 0.002 two thousand five hundred times
   does not give exactly 5.0 in floating point, so `data->time < duration` is true once
   more. With 1.0 it happens to come out at 500.
3. Copying the handle: "error: use of deleted function 'std::unique_ptr<_Tp,
   _Dp>::unique_ptr(const std::unique_ptr<_Tp, _Dp>&) [with _Tp = mjModel_; _Dp =
   cell::ModelDeleter]'". "Deleted function" is the copy constructor, removed on
   purpose.
4. Without the `*`: "error: invalid initialization of reference of type 'const
   mjModel&' ... from expression of type 'cell::ModelPtr'", with a note pointing at
   `MakeData`'s declaration in `mj_handles.h`.
5. `step_test` passes. Ways to fail a test: change the expected joint count, or the
   time step in `OneStepAdvancesTimeByTheTimestep`.

## Questions to ask

1. *Explain.* Why are there two objects, `mjModel` and `mjData`, and not one?
   A good answer covers: what is constant against what changes; several states for one
   model (scratch copies, one per thread); resetting the state without reloading.
2. *Predict.* (Before lab run 2.) How many steps for five seconds?
   A good answer after the run covers: floating-point sums; never compare an
   accumulated time with `==`; the repository's tests bound counts and use
   `EXPECT_NEAR`. If stuck, point at: `StateStaysFiniteAndWithinJointLimits` in
   `tests/step_test.cc`, which allows one time step of slack.
3. *Locate.* Where is the model freed if `LoadModel` succeeds but the program returns
   early later on?
   A good answer covers: nowhere in the text; `ModelPtr`'s destructor runs when `model`
   goes out of scope, on every `return`; it calls `ModelDeleter::operator()`.
4. *Explain.* `MakeData` takes `const mjModel&`; `mj_step` takes `mjModel*` and
   `mjData*`. What does each signature tell the caller?
   A good answer covers: the reference cannot be null and will not be changed; the C
   function says nothing (it is C), and in fact changes only the data.
5. *Pitfall.* What would happen if `ModelPtr` were `mjModel*` and `main` returned early
   on a later error?
   A good answer covers: a leak, silent, found only by a tool or a long-running
   process. And the opposite mistake, deleting twice, is a crash at best.
6. *Transfer.* What plays the part of `unique_ptr` in a language you know?
   A good answer covers: Python's `with`, Java's try-with-resources, Go's `defer`,
   Rust's ownership (the closest). The difference: in C++ it is how all memory is
   handled, not only files and locks.
7. *Explain.* Why does `step_arm` print 0.024 rad at the shoulder with no command sent?
   A good answer covers: no command means "hold zero"; gravity; a servo that pushes in
   proportion to the error must have an error to push.

## Misconceptions to listen for

- "`const mjModel&` makes a copy." It makes no copy; that is its point.
- "The header is compiled." Only `.cc` files are; a header is text pasted into them.
- "`unique_ptr` is slow." It is a pointer with a destructor; it costs nothing at run
  time.
- "`mj_step` runs in real time." It runs as fast as the machine can; nothing waits.
- Reading `model.get()` as transferring ownership.

## Questions the student may ask

- *Why pointers for outputs and references for inputs?* A house rule from the Google
  style this code follows: at the call site, `&x` or a pointer shows that `x` may be
  written. See how `SolveIk` in `src/ik.h` takes `mjData* scratch` and `const Arm&`.
- *Why not exceptions when loading fails?* The repository uses none. A function that
  can fail returns something empty and, optionally, a message. Stop 3 looks at
  `std::optional`, the usual form.
- *What is `mjtNum`?* MuJoCo's floating-point type, `double` in this build.
- *Why a UR10e here when the cell has a KUKA?* History: it was the stand-in until the
  KUKA model existed (`MODULE.bazel` says so). It still checks the toolchain.
